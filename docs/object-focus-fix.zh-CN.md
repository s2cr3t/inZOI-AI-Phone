# 物品查找与行动衔接修复（基于 2.49.0 的开发版）

复现来源：`logs/bridge-20261024.log`，宗会荣与钟亚廷在中央公园抓娃娃的对话，日志原始时间 10:53:23–10:56:59。

## 已修改

- `repairActions` 显式接收会话双方信息，消除 `pair is not defined`；补救后保留延后约定。
- 将模型失败、游戏接口失败、内部异常、未匹配物品和没有可用动作分开记录。内部异常不再解释成到处找不到东西，也不写入角色的失败后续情绪记录。
- 扫描到却没有动作的物品保留在名称列表中。根据当前目标提升相关物品，并为最多六个候选重新查询可用动作。
- 部分名称、类别名称优先直接匹配；俗称及带位置参照的描述必要时进行一次只读语义选择，同一目标的追问复用选择结果。
- 在内存中保存最多十分钟的当前目标。位置和进展追问不重复下达动作；换地点重新核实候选，完成、取消、换目标和玩家接管分别处理。读档及清空对话时清除目标。
- 单个已接受的物品任务不再被无关社交动作拖延；明确先后顺序、多物品任务、背包后续动作保持原顺序。只有立即行动的承诺遇到少数已知闲坐/自主玩耍动作时自动让位；上学、工作及端饭保护仍由原有调度执行。
- 对该流程排队的物品任务，在执行前再次核实地点及可用动作，保留占用检查。
- 增加目标候选、筛选方式、失败类别以及准备、模型、规划耗时日志。

## 验证

离线回归运行：`node --test sms-bridge/tests/object-focus.test.js`。
测试使用替身接口，不连接模型、不移动游戏角色、不写入玩家聊天或存档。

当前验证不等同于完整真人游戏复测：模型是否每次都选中正确候选、寻路和动作耗时，仍需在实际对话中观察新增日志。没有承诺固定秒数完成，也没有更改安装包或 Lua 模组。
